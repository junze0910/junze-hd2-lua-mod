> 改成一个可配置的 mod —— **不再需要"二选一"**，因为只有一份记录会被写。

## 三、三个结构性事实（写 mod 必须知道）

1. **每台只填 2 槽**（槽0 左 / 槽1 右），槽2~4 永远是 0 → 空槽是天然自检条件。
2. **node 只有两套**：`1137513325/3282525496` 被爱国者+突破者共用；`537031082/1641276944`
   被解放者+伐木者共用。**node 对得上不足以确认改对了机体** —— 必须走
   「索引区实体哈希 → recIdx → 记录」，node 只能当二级复核。
3. **`pad` 固定**：左臂 = 2、右臂 = 1。白送的第三个校验条件（旧模组没用上）。

## 四、⚠ 两条前置的差别（新模组的核心约束）

| 要改的 | 所在表 | 怎么定位 | Scanner 能给吗 |
|---|---|---|---|
| 手臂槽位 | `MountComponentData` `0x3845B1E0` | 索引区 `(u64 实体, u32 recIdx, u32 pad=0)` | ✅ **能给** |
| `additional_stratagem` | `StratagemSettings` `0x30EB789E` | 按 **package 值内容搜**（该表在内存里**不是 LDLD 块**） | ❌ **给不了** |

所以本模组是**一条腿接 Scanner、一条腿自扫**：
- 手臂走 Scanner（`S.poll(0x3845B1E0)` → 广播的基址 → `magic + recIdx*120`）
- 战备附加沿用旧模组那套内容搜（`package` 命中 → `+8` icon 复核 → `+32` 写入）

## 五、自引用保护（取代旧的"二选一"）

旧两版必须二选一，是因为两条记录互相附加会形成"战备套娃"并在载入列表时崩溃。
本模组只有一条记录被写，**天然没有互相附加**；但必须防**自引用**（附加 = 携带）：

- **UI 层**：附加机体的候选列表里直接不出现携带机体（三选一的由来）
- **运行时**：写入前再断言 `附加ID ≠ 携带ID`，不等就拒写并记日志

### 6.1 为什么战备附加值得做新探针

`DESIGN` 原本写着「该表在内存里不是 LDLD 块」，但 Scanner 现在的探针**只认两个固定偏移**
（组件区段 `+0x8111C` 门、独立表 `+0x4`）——**偏移不在这两处的表一律扫不到**，
哪怕它是标准 LDLD 块。所以"三次会话都没出现"只能证明它不在这两个偏移上。

若探针成立，收益是双份的：本模组不用内容搜，**且 StratagemSettings 可以加进 Scanner 广播**，
外骨骼系 mod 从此不必自扫。

## 七、⚠ 常量必须用十六进制字符串，不能用 Lua 数字（SKILL 6.1）

本模组的 u64 常量（实体哈希 / package / icon / 全部臂件 item）都是 1e18 量级，
**超过 2^53**，LuaJIT 的 number 存不下：

```
7298250363396168598  ->  7298250363396168704     差 106（自检实测抓到）
```

所以一律存 **16 位 BE 十六进制字符串**（`'65489809A8181B96'`），内存里要比的 LE 字节串
用 `le()` 现转；只有 node / recIdx / pad 这种小整数才用 number。cfg 里也写十六进制。
